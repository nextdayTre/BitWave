# Decision log

Implementation decisions taken to keep the plan moving. Each one is reversible
while the codebase is small; the ones the plan marked for the author are noted.
Format is deliberately short: decision, basis, how to reverse it.

**Status:** 2026-11-06 · applies to the `src/core` extraction, the F0 baseline, the browser-verification harness, the `window.BitWave` seam, the Vite build (D19), the F2 state/render/UI spine (D20–D23), the F3 source table (D24–D25), the F4 accessibility floor + IA pass (D26–D32), F5 persistence & reach (D33–D36) and F6 distribution (D37–D38).

| D15 | **Frame names are global.** Lane 1 = A/B/Z1, lane 2 = C/D/Z2, lane 3 = E/F/Z3. The six operand frames A–F are the six routing destinations; the nine frame outputs A–F + Z1–Z3 are the sources. | D16 | **A frame click is a focus lens, not a view switch.** `selectFrame()` no longer exits 3-D or closes the navigator; it sets the lane's `focus`, retargets strip/readouts/truth/stage, keeps operands editable and shows a derived frame read-only. `enableBOnSlot()` no longer steals focus. | Author request 2026-11-06 ("clicking a frame in the Lanes tab more like a Focus feature"); the 3-D view kept showing B statically and a frame click dropped to 2-D. | Restore the forced 2-D branch and `closeFrames(true)`; the browser check's focus assertions fail. |
| D17 | **Visibility eyes are per lane.** `frameVis` moves from one global `{a,b,z}` to each slot, so hiding A in lane 1 does not hide C in lane 2. | With global names, "frame A" is lane-1-specific; a single global toggle would silently hide three different frames. | Return to one shared map; eye labels would need to be generic again. |

| D19 | **The build toolchain is installed and the artifact is generated.** Source is `src/index.html` + `src/main.js` + `src/styles/app.css`; `npm run build` (Vite 8.3.6 + `vite-plugin-singlefile` 2.3.4, **no minification**) emits the single-file `bitwave-v2.html`; `npm run dev` serves the source; `npm run typecheck` checks the core. | D20 | **The state tree is a DOM-free module behind a transaction store.** `src/state/instrument.ts` owns the singleton `S`, factories, global frame names and focus/edit selection, delegating nibble/register/derive math to `src/core`. `src/state/store.ts` is a generic `createStore` whose `patch()` collapses nested transactions into one revision and one notification pass. `commit()` in the app runs inside it. | F2's spine needs one tree and one write boundary; the IIFE held state and DOM together. | D21 | **Register writes go through `src/state/actions.ts` and the app's evaluator is the core `evaluateAll()`.** `src/state/routing.ts` presents the app's slots as a core `LaneMap` with shared registers; `evaluate()` runs routes in dependency order then derives every lane's Z. The app's `recomputeZ` duplicate is gone. | F2's rule is base writes first, one clocked evaluation, then renderers. Evaluating through the real core engine (rather than per-lane recomputation) is what makes adding the matrix a data change instead of a second implementation. | Revert handlers to direct `S` mutation and `recomputeZ`; `tests/actions.test.ts`, the edit-path browser check and parity fail. |
| D22 | **The render layer is its own module group.** `src/render/canvas.js` owns the 2-D curve, 3-D field, legend, `fitCanvas` and `--pad`; `src/render/strip.js` owns the editor strip and its fast patch; `src/render/readouts.js` owns hex/dec/truth/trend/3-D rows.
