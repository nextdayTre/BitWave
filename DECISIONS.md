# Decision log

Implementation decisions taken to keep the plan moving. Each one is reversible
while the codebase is small; the ones the plan marked for the author are noted.
Format is deliberately short: decision, basis, how to reverse it.

**Status:** 2026-11-06 · applies to the `src/core` extraction, the F0 baseline, the browser-verification harness, the `window.BitWave` seam, the Vite build (D19), the F2 state/render/UI spine (D20–D23) and the F3 source table (D24–D25).

| # | Decision | Basis | Reverse by |
|---|---|---|---|
| D1 | **Accessibility is in scope in both senses** (WCAG and reach); WCAG P0 (F4) lands before persistence (F5). | PLAN §9 Q1 recommendation. The keyboard/nibble model is reused by routing and share. | Reorder F4/F5 in the roadmap; no code implication yet. |
| D2 | **Routing semantics:** cross-view cords + within-view feedback; sources `A/B/Z`×3; destinations `A/B`×3; Z is never a destination; **one cable per input**; feedback gets one-evaluation `z⁻¹` delay; patched inputs are driven and lock local edits. | PLAN §9 Q2–Q5 recommendations; routing deep-dive §2–§3. Implemented in `src/core/routing.ts`. | Change `addRoute`/`evaluateAll`; tests pin the current contract. |
| D3 | **Park/restore is byte-identical on unplug**, including across resize via `remapParked`. | Reuses the LFO's promise (DESIGN §10.18); routing §3.1. | Replace park map with a different policy; tests assert the contract. |
| D4 | **Lane naming:** lanes are **1 / 2 / 3** in UI, docs and code; letters belong only to frames/operands (A, Z, B). Persisted keys are `"1"/"2"/"3"` too. | Author decision 2026-11-06 (closes PLAN Q6); removes the "A.A" ambiguity. | Pre-release `.bitwave` schema stays 1; a rename migration would be one field. |
| D5 | **Core technology:** native Node TypeScript (type stripping) + `node --test` with **zero dependencies**; Vite/`tsc`/Playwright scaffolding is deferred until the environment can run them. | Node 24.14.1 runs `.ts` directly; the sandbox blocks Chromium and process-piped test runners, so a dependency-free harness is the only verifiable path in-session. | Swap the runner for Vitest later; module imports already use explicit `.ts` extensions and `tsconfig.core.json` is ready. |
| D6 | **`N` is an explicit parameter in the core**; no global state, no `curSlot()` default. The app's one shared width becomes a store concern. | DESIGN §10.10; PLAN §6.3. Implemented throughout `src/core`. | Reintroduce a façade in `state/`, never in `core/`. |
| D7 | **Evaluation is clocked, not algebraic:** `evaluateAll` runs on transactions, samples delayed sources before writing, resolves views in dependency order, then derives Z. | routing §3.2–§3.3; avoids stale Z and hung loops. | Change evaluation policy in one function; tests cover chains/cycles. |
| D8 | **DESIGN §11 `NOT` vector is an erratum.** The real complement of `FEDCBA9876543210` is `0123456789ABCDEF`; the doc lists `123456789ABCDEF0`, which is neither the complement nor consistent with `invert`. | Verified independently; index.html's `invert` agrees with the engine. | Correct DESIGN.md §11 (recommended); the test documents which value is authoritative. |
| D9 | **The `.bitwave` document persists A/B hex, lane settings, routes and parked bases — never Z.** Schema 1; a newer schema is rejected with a distinct `newer-schema` code so the UI can offer read-only. | PLAN §6.5; DESIGN §10.8; routing park/restore needs its bases to survive reload. | Bump `PROJECT_SCHEMA` + add a migration chain; old files keep loading through the old branch. |
| D10 | **Dimming is hands-off.** No changes to `--dim`, `--dimmer`, `--line`, alpha values or contrast. Colour and intensity are a future mapping axis. | Author decision 2026-11-06 (closes PLAN Q8): "The tool is not a toy." | Reopen only as an explicit mapping-layer design task. |
| D11 | **Routing is the existing CSV column mechanism, housed as a six-row source table.** Each fixed operand input (A/B × lanes 1–3) gets one SOURCE select listing imported data columns first and frame outputs second. STATE is `data` / `1:1` / `z⁻¹` / `—`. No add/remove rows, no matrix toggle, no separate import path, no cables/jacks/drag/3-D overlays. CSV loading, typing and alignment are unchanged. | Author decision 2026-11-06: "Matrix is the structural housing for this, that is all." | UI-only; the routing engine and CSV path are unchanged. |
| D12 | **The cable dock spike is retired.** `spike/patch-dock.html` and `docs/diagrams/patch-model.svg` are removed; `spike/routing-matrix.html` is the single reference prototype. | Same decision: one clear prototype beats two. | Git history retains both. |
| D13 | **Browser verification is a checked-in, zero-dependency CDP harness.** `tools/browser-check.mjs` drives the shipped file over `file://` with Node's built-in WebSocket/fetch; Chromium is auto-detected (Playwright cache, Chrome/Edge, or `BITWAVE_CHROME`). `npm test` stays browser-free; `npm run check:browser` is the artifact gate. | The sandbox that blocked headless Chromium no longer applies; PLAN F0's browser gap closes without adding Playwright/Vitest (D5 stands). | Delete the script and npm script; verification reverts to manual/CI-only. |
| D14 | **`--pad` has one writer and one reader.** `fitCanvas()` computes it once (16px at or below 720, 40px above) and stores it in `PAD`; `draw()` reads `PAD` instead of recomputing its own 680px threshold. The CSS media query stays as the pre-JS fallback. | The browser check found the app writing `--pad` with a 680px threshold while CSS/DESIGN §5/§9 use 720, and `draw()` re-deriving a second pad — the DESIGN §10.4 desync (canvas inset ≠ strip gutter). | Revert the three lines in `fitCanvas`/`draw`; the §5 strip assertion in the browser check fails if the two disagree again. |
| D15 | **Frame names are global.** Lane 1 = A/B/Z1, lane 2 = C/D/Z2, lane 3 = E/F/Z3. The six operand frames A–F are the six routing destinations; the nine frame outputs A–F + Z1–Z3 are the sources. Persisted `.bitwave` frame keys stay per-lane `a`/`b`/`z` (schema 1 unchanged) — the global names are a presentation mapping (`FRAME_NAMES`). | Author decision 2026-11-06 ("simplification on the default/non-CSV Frame/Lane naming conventions"). Removes the per-lane A/Z/B ambiguity and lets the matrix list six unique rows. | Change the `FRAME_NAMES` map, the spike's `FRAME_OUTPUTS` and the doc tables; no data migration. |
| D16 | **A frame click is a focus lens, not a view switch.** `selectFrame()` no longer exits 3-D or closes the navigator; it sets the lane's `focus`, retargets strip/readouts/truth/stage, keeps operands editable and shows a derived frame read-only. `enableBOnSlot()` no longer steals focus. | Author request 2026-11-06 ("clicking a frame in the Lanes tab more like a Focus feature"); the 3-D view kept showing B statically and a frame click dropped to 2-D. | Restore the forced 2-D branch and `closeFrames(true)`; the browser check's focus assertions fail. |
| D17 | **Visibility eyes are per lane.** `frameVis` moves from one global `{a,b,z}` to each slot, so hiding A in lane 1 does not hide C in lane 2. | With global names, "frame A" is lane-1-specific; a single global toggle would silently hide three different frames. | Return to one shared map; eye labels would need to be generic again. |
| D18 | **The agent/test seam is a read-only `window.BitWave` (schema 1).** `state()`, `geometry()` and `frames()` return deep-frozen plain objects; there are no setters and the global is defined non-writable. `geometry()` returns computed control-point `xs[]` plus DOM nibble rects so tests assert the DESIGN §11 alignment without scraping pixels. | AGENTS.md asks for explicit local state/render surfaces over screenshot automation; the browser harness needed a non-circular way to prove the canvas and strip agree. | Remove the surface block in `bitwave-v2.html`; the harness agent checks and the geometry assertion fail. |
| D19 | **The build toolchain is installed and the artifact is generated.** Source is `src/index.html` + `src/main.js` + `src/styles/app.css`; `npm run build` (Vite 8.3.6 + `vite-plugin-singlefile` 2.3.4, **no minification**) emits the single-file `bitwave-v2.html`; `npm run dev` serves the source; `npm run typecheck` checks the core. Rebuild parity is a gate: `tools/browser-check.mjs --compare` requires identical screenshots across six states. The zero-dependency `node --test` runner from D5 stays. | PLAN §6/§7 F0 requires multi-file source with single-file delivery, and the sandbox that blocked npm/Chromium no longer applies; the D5 deferral is over for the build toolchain only. | Delete `vite.config.mjs`, `tools/build-artifact.mjs` and the `src/index.html`/`main.js`/`styles` tree; the app reverts to editing the HTML directly (git history has both). |
| D20 | **The state tree is a DOM-free module behind a transaction store.** `src/state/instrument.ts` owns the singleton `S`, factories, global frame names and focus/edit selection, delegating nibble/register/derive math to `src/core`. `src/state/store.ts` is a generic `createStore` whose `patch()` collapses nested transactions into one revision and one notification pass. `commit()` in the app runs inside it. | F2's spine needs one tree and one write boundary; the IIFE held state and DOM together. Moving the tree out is the first slice; renderers and the remaining writers follow. | Move the tree back into `main.js` and `commit()` out of the store; `tests/state.test.ts` and the parity gate fail. |
| D21 | **Register writes go through `src/state/actions.ts` and the app's evaluator is the core `evaluateAll()`.** `src/state/routing.ts` presents the app's slots as a core `LaneMap` with shared registers; `evaluate()` runs routes in dependency order then derives every lane's Z. Unary ops/presets delegate to `src/core/ops.ts`; drag, bit/wheel, ops/presets, CSV step, resize, binop, LFO tick, copy and unpair all run inside `store.patch`. The app's `recomputeZ` duplicate is gone. | F2's rule is base writes first, one clocked evaluation, then renderers. Evaluating through the real core engine (rather than per-lane recomputation) is what makes adding the matrix a data change instead of a second implementation. | Revert handlers to direct `S` mutation and `recomputeZ`; `tests/actions.test.ts`, the edit-path browser check and parity fail. |
| D22 | **The render layer is its own module group.** `src/render/canvas.js` owns the 2-D curve, 3-D field, legend, `fitCanvas` and `--pad`; `src/render/strip.js` owns the editor strip and its fast patch; `src/render/readouts.js` owns hex/dec/truth/trend/3-D rows. Spline comes from `src/core/spline.ts`, CSV parsing/typing/alignment from `src/core/csv.ts`, and the dataset singleton moved to `src/state/dataset.ts`. View-state writers (lane select, split/3-D, copy arming, frame visibility, LFO controls) now run inside `store.patch` too. The render modules are `.js` during extraction; they migrate to `.ts` when the render layer is typed. | F2 needs renderers that read a settled tree rather than sharing a closure with input handlers; the `--compare` gate proves the extraction is pixel-identical. | Move the modules back into `main.js`; the renderer import graph and parity checks fail. |
| D23 | **UI features are modules with injected callbacks.** `src/ui/frame-navigator.js` (panel + focus lens), `stage-bar.js` (lane/split/expression), `keyboard.js`, `csv-import.js` (import + stepper) and `controls.js` (ops/presets/binop/size + LFO) own their DOM; selection/view orchestration is injected by the composition root. `src/io/observations.js` owns the logger/export. `main.js` drops from ~2,450 to **843 lines** and keeps composition, pointer input, lane/view controllers, loop/boot and the agent surface. | F2's UI split: DOM stays local to each feature, the spine stays shared, and each module can be reasoned about alone. Two controllers (pointer, lane/view) remain in `main.js` and follow without behaviour change. | Move modules back into `main.js`; the parity gate and feature checks fail. |
| D24 | **F3 ships as a six-row source table with assignment labels.** `src/ui/source-table.js` (opened from the data group) renders the six operand inputs A–F over `src/state/bindings.ts`. A row reads one of a CSV column (`data`), a frame output (`1:1`/`z⁻¹`) or `—`; the label carries the assignment (`A · Hex 1`, per the author's 2026-11-06 note). Data/frame choices clear each other; a fresh import resets the board; the per-lane `colA`/`colB` selects are retired. Driven inputs are locked and unplug restores the parked base (D2). | D11 says routing is the existing CSV column mechanism housed as a matrix; the author's note asks the frame label in the matrix to equal the frame assignment from the CSV column. | Revert the panel and bindings module; `tests/bindings.test.ts` and the browser source-table checks fail. |
| D25 | **The matrix is a transient panel, not a mode.** A `sources` button in the data group opens the table; Esc or an outside click closes it. It adds no view mode, no routing toggle and no sixth band — the stage stays 2-D/3-D as before. | D11 forbids a new subsystem/mode, but six rows need vertical room the control band does not have at 360 px. | Render it inline in the data group; the panel open/close checks change. |
