annotations — dashed outlines + numbered circles are review markup, not UI

One line per decision. Numbers 1–8 match the markers on the instrument; 9–10 are closing notes. The cards at the foot are the scope and the open questions.

1

logic ▦ joins the mode list

The motion group keeps its one transport (LFO), the mode select and the rate. logic ▦ selects the program and the opener button (shown aria-expanded) toggles the panel, exactly like sources opens the source table. Selecting another mode closes the panel; selecting logic re-opens it.

2

Transient panel, no new view

It floats over the stage at the right, below the stage bar, in the same overlay convention as sources (which uses top/bottom 8); it reuses .fp-head/.fp-title and closes on its × or Esc with focus returned to the opener. The panel follows the stage bar's focused lane — no second lane picker. The stage bar is drawn left-aligned here only so it stays clickable beside the open panel.

3

One instruction per step

Eight fixed steps in the first slice. A step is one existing verb — a unary op with an amount, one of the eight presets, or rest — so the program is a composition of the tested src/core/ops.ts operations, not new maths. The bar under each step is its amount; preset/rewrite steps draw a hollow marker, rest a dash.

4

Playhead = the LFO clock

One step executes per tick, cumulatively: two ROL 4 steps read as ROL 8, NOT toggles, rest holds. The highlight marks the next step; the footer names the tick. Rate is the existing 1–8/s select; reduced motion caps it at 4/s.

5

Direction

forward loops 1→8; pingpong runs 1→8→1. Changing direction restarts the shape cleanly, like changing the mode does today. Length stays 8 in this slice (see open questions).

6

LFO stays the play button

No second transport. The existing toggle starts/stops every motion mode, logic included; the panel footer reports running/stopped. This keeps one authoritative on/off and the snapshot/restore discipline behind it.

7

B phase is disabled, not removed

In logic mode b sync / anti / +¼ / +½ does not apply; it stays in place disabled with a reason (reserve space, §9). This is also the open operand-scope question: v1 moves the lane's first operand only (A/C/E); both operands with the B-phase rule is a later decision.

8

Stop restores the snapshot

Exactly the existing promise (§10.18): pre-run operands are held and put back byte-identically on stop; the register you hand it is the register you get back. Switching lanes while running does not stop the clock — each lane runs its own program.

9

Every tick is a real commit

The wave, hex, strip, truth table and Z read the actual post-tick state — no interpolation, no frames that pretend to be values (§10.18–20). The mockup's wave and meta are driven the same way, so what you see is what a real tick would hold.

10

Palette and geometry untouched

Accent green only, at existing alphas; mono for values, sans for labels; no new hue, no node graph, no second view. The stage bar, module order, strip and truth table stay where they are — this is an addition to motion, not a redesign.

open at review

  • Operand scope: first operand only (shown: A/C/E, B static) or both operands with the existing B-phase rule (sync/anti/+¼/+½)?
  • Length: fixed 8, or a 4/8/16 length select (reserved space, like rate)?
  • Narrow widths: the step grid scrolls horizontally at 420 px; a 2×4 grid is the alternative.
  • Share/agent: program in .bitwave schema 3 and window.BitWave schema 2 is planned, not drawn here; the share budget needs measuring at 256 bits.
  • Naming: mode label logic ▦ vs program vs seq; panel title “lane logic” is the working name.

deliberately not in this slice

  • Operator steps (changing the binop per tick) — they would need the operator in the snapshot/restore contract.
  • CSV data steps — the existing step ⏭ mode already owns dataset stepping; mixing it into a register program muddies stop/restore.
  • Conditionals / branching — this is a sequencer, not a scripting language.
  • A text editor or node graph — the step grid is the program; no new visual system.

Mockup-only mechanics, transparent: the width slider, hex entry, import/stepper, presets, unary ops, binop set and view controls are drawn for context and are inert. The wave is a straight polyline (the app draws the monotone-Hermite spline); the strip, truth table, source table, 3-D field, project menu and observation logger are omitted from the crop. The stage bar is left-aligned so the lane selector stays usable beside the open panel (the app centers it; sources can overlap it today). Other mode options disable the transport because only logic mode is simulated here.
